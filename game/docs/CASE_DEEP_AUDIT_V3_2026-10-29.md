## 结论

本轮重新进入案例并补录启动/大厅/序章，再结合此前已观察的首场战斗教程，验证了可见顺序：

```text
三角色主视觉加载屏 -> 万圣节大厅（设置/游玩/保存进度/版本/Profile/全屏）
-> 医疗舱暗场与 `???` 局部剪影 -> 大尺寸角色醒来/身份揭示/逐句对白
-> 安全跳过入口 -> 街区战场建立 -> 双角色关系/身份对白
-> 阵营与回合 HUD -> 敌我单位数值 -> 教程肖像和气泡
-> 高亮可执行格 -> 拖动单位 -> 选中单位 -> 指向攻击目标
```

案例的强项是叙事连续性和教学反馈，而不是卡牌系统。当前可见战斗是回合制战术网格：角色在地图格子上移动，攻击/生命值显示在单位上方，教程用蓝框、手形光标和右下角色肖像把玩家引导到下一步。没有观察到牌组、手牌、抽牌堆、弃牌堆、费用或卡牌结算。因此项目必须借鉴案例的镜头、角色、对白和教学编排，但不能把案例战斗当作真卡牌实现证据。

当前项目目标是离线本地 Android 战术 RPG，仍应保持 `Vertical Slice / 案例对照部分通过`。要达到生产标准，必须证明：原创大尺寸动态角色、连续序章事件链、三路战术战斗、胜利余波、奖励存档/回大厅、可重复截图/日志和 Android 验收。

> **方向更正（2026-10-29）**：此前报告把技能库中的 CCG 基线误写成本项目必做规则，造成 20 张牌组等错误工作要求。本项目以用户明确指定的“保留原玩法、离线本地 Android 化”为准：不得引入或保留 CCG 手牌、能量、抽牌堆、弃牌堆规则。该错误方向不再作为验收标准。

## A. 本轮浏览器实测（Verified）

### A1. 医疗舱剧情

- 画面以医疗舱背景和大尺寸凯蒂立绘建立地点；角色中心占据主要视口，不是小头像或小单位。
- 对白以“凯蒂”身份牌和横线文本呈现，逐句推进；右下持续出现“轻触以继续”。
- 角色保持大尺寸构图，背景、角色、文本有清晰分层；不是纯文本页面。
- 连续演出阶段右上出现“跳过”，并有静音/内容控制入口。
- 进入成人内容后立即点击“跳过”；该内容不作为美术、动画、镜头或产品功能依据。

### A2. 启动与大厅（本轮新增）

- 启动先呈现三名角色组成的宽幅主视觉与品牌标识，底部黄色进度条；随后进入大厅，加载提示短暂覆盖于背景上。
- 大厅是全屏场景，不是菜单卡片拼接：万圣节户外背景、4 名角色有前中后景和高低错落构图，角色道具与环境色统一。
- 主操作 `游玩` 是最强视觉按钮，`保存进度` 次级；右上齿轮为设置，右下显示版本 `23.0.1`、Profile ID 和全屏按钮。页面下缘为站点法律/客服信息（本地离线产品不需要复刻网页广告/站点 footer）。
- 进入游玩后，医疗舱先以黑场/暗角和局部剪影制造悬念；角色从局部揭示到完整全身站姿，姓名从 `???` 揭示为凯蒂。单句对白置于角色下方横线区域，右下持续显示继续提示；切换对白时角色保持大尺寸，表情/姿态有轻微变化。
- 桌面视口下游戏画布以 16:9 居中显示，外围延续虚化场景背景；右下全屏按钮始终处于画布外沿。当前页面底部广告/法律 footer 占用首屏空间，是网页发行环境特征，不应移植到离线 Android。

### A2. 剧情关系和战斗入口

- 跳过后切到街区俯视战场，场景和人物关系延续到战斗空间。
- 战斗前对白再次展示凯蒂与另一名持枪女性角色同框，另一角色初始姓名显示为 `???`，形成身份悬念。
- 战斗 HUD 顶部显示双方阵营“伊桑 / 黑手党”，底部显示“回合 1”。敌方单位在右上、我方单位在左下，双方有红/绿底圈区分阵营。

### A3. 战斗教程动作序列

1. 教程框说明敌人拥有“4 攻击力和 3 生命值”，敌方单位上方显示 `4 / 3`。
2. 蓝色矩形框锁定敌方单位，并配右下凯蒂教程肖像和“轻触以继续”。
3. 教程把可执行格染成蓝色，并用大号手形指针指示格子。
4. 玩家拖动单位后，单位实际移动；高亮区域和单位位置发生变化。
5. 选中我方单位时，右侧出现单位信息面板（“战士 / 维和者 / No Skills”），移动范围格被标出。
6. 教程再次用指针要求选择目标格，再要求以我方攻击力 3 指向敌方单位；动作目标是可执行的，不是只读说明。
7. 每一步都产生可见反馈：选中环、移动范围、手形引导、角色对白、数值/血条和回合 HUD 持续存在。

本轮没有把战斗推进到完整胜利结算；胜利、奖励、主大厅回流沿用本项目已有的暖机快照记录，不能伪装成本轮重新观察。

## C. 对制作指南的具体约束

### C1. 首分钟必须采用的镜头逻辑

```text
BOOT_READY
 -> SCENE_ESTABLISH：环境、暗角、镜头焦点
 -> HERO_WAKE：大尺寸主角、呼吸/眼神/入场动作
 -> IDENTITY_REVEAL：姓名、身份、第一句对白
 -> ALLY_RESPONSE：第二角色或无线电肖像回应
 -> CONTEXT_OBJECTIVE：地点、阵营、威胁和一个可执行目标
 -> STORY_TO_BATTLE：保持地点/角色上下文，切入战斗
 -> BATTLE_READY：战场、双方单位/阵营、回合 HUD、合法移动格/目标和首个合法动作
```

每个事件要有 `id`、开始/完成/跳过状态、角色或背景资源、对白、音频 cue、VFX cue、时长和断言。跳过只能跳过表现，必须完成剧情标记、战斗初始化和音频停止。

### C2. 角色、动画和特效门槛

- 主角故事图/骨骼在桌面和手机视口均应达到视口高度 65%～80%，脸、武器、姓名牌不得被对白框遮挡。
- 动作最低集合：`idle`、`wake/enter`、`talk`、`react`、`attack`、`hit`、`victory`。原生骨骼和 CSS/合成回退必须分开记录。
- “动”不能只做位移或透明度；至少要有呼吸/眼神、姿态、镜头推拉或局部动作之一。攻击/技能命中必须有 marker、命中特效、数字/状态变化和音效。
- VFX 按事件 ID 记录场景建立、身份揭示、战术目标锁定、移动、攻击/技能命中、状态、胜利余波。Reduce Motion 关闭震屏、闪白、速度线和长粒子路径，但保留状态、颜色和文本反馈。

### C3. 三路战术 RPG 战斗闭环

1. `battle_ready` 显示三路/网格、我方与敌方单位、阵营区分、回合数、攻击/生命值、可选单位和当前教程目标。
2. 选择我方单位后显示移动范围、单位信息和可执行技能；拖动或点选只能落在合法格/合法目标。
3. 选择攻击目标后执行攻击或技能：播放角色动作 marker、命中特效、受击反应、伤害数字/生命条变化和音效；结算完成前禁止重复提交。
4. 结束我方行动后进入敌方回合，显示敌方目标/行动反馈，再返回下一回合；战斗事件可按种子重放。
5. HP 归零触发死亡/退场，所有敌方单位归零才进入 `victory`；失败进入 `defeat`，不能用自动战斗或静态按钮代替。
6. 胜利后依次出现角色 victory、战报/星级、奖励发放、存档完成、返回大厅；重新加载后进度仍存在。

此前“20 张牌组、5 张手牌、Mulligan、3~10 能量、抽牌堆/弃牌堆”属于错误 CCG 方向，不得继续实现或作为验收项；若代码仍包含这些 UI/状态，应移除或隔离。
