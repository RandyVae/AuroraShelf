# 验证记录 — 144（撤回 VOD/预热，恢复稳定直播播放器）— 2026-10-24

## 问题

143 的"VOD 封面遮挡 + 房间页预热"在真实 Stripchat 页面上不可靠：

1. 直播 WebView 未就绪时，VOD 快照封面会无限循环；快照本身含站点 bumper/广告画面，用户看到的就是"纯广告、不播放内容"。
2. Stripchat 对未确认年龄的访客返回 18+ 年龄确认页；播放器脚本提前把整页隐藏，确认按钮不可见，视频永远不会加载。
3. 检测脚本随后超时，错误浮层压在页面/视频上。

## 处理（144）

- **移除** VOD 封面播放器与房间页预热接管（`LiveVodPreview`、`LiveRoomPrewarm`），恢复 142 的稳定 WebView 播放器链路。
- 保留一个必要修复：**不再在页面加载前隐藏整页**。只有检测到视频元素后才注入沉浸样式，因此 18+ 年龄确认页/站点必要交互对用户可见、可点击。用户自行确认年龄后，视频正常加载再进入沉浸播放。
- 版本 144，本地预览包 `dist/AuroraShelf-2.15.0-144-live-restore-LOCAL.apk`（SHA-256 `ab532ab7…`）。

## 验证状态

- `emulator-5554`：页面可加载、18+ 页可见；但在本轮测试会话中，确认年龄后站点返回的访客页面未稳定给出可播放的视频元素（服务端年龄/访客状态与广告逻辑在自动化环境下反复变化），**未能取得"确认年龄 → 视频就绪"的稳定截图**。
- 因此本版只声明：已移除广告封面与提前隐藏页面的缺陷；不再声明"即点即播"或"视频必然出画"。
- 此前记录的 143 数据（VOD 0.05–0.1 s、直播 0.3–0.5 s）只在特定访客状态下成立，不能作为普遍结论。

## 下一步建议

1. 在真机上用普通浏览器确认同一房间可播放（排除网络/访客限制），再回到 App 验证。
2. 若站点对访客强制广告/年龄门且 App 内 WebView 仍卡住，提供"在系统浏览器打开"兜底入口（复用现有 URL），比继续在 WebView 里对抗站点更可靠。
3. 若要继续做"即点即播"，需先抓取并保存站点的年龄/访客 cookie（用户手动确认一次后复用），再考虑页面预热；仅缓存页面 HTML 无法绕开视频初始化。
