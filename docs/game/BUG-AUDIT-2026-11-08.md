# 三端游戏缺陷复审报告

审计日期：2026-11-08  
范围：Android 手机、Android 平板、iPhone、iPad 游戏容器与共享游戏逻辑  
基线：`FULL-AUDIT-2026-11-08.md` 与当前工作树源码  
证据：本轮为源码和配置复审，真实设备逐项运行仍需补证。

## 总体结论

本轮没有把“能编译”当成缺陷关闭。已确认的风险主要集中在三端容器行为不一致、游戏状态中断恢复、付费/救济逻辑、Canvas 无障碍和 Slot/战斗叠层。Android 手机与 Android 平板共用固定竖屏 Activity，iPhone 与 iPad 共用同一个 Web 游戏布局，三端都存在未完成的运行验证。

## 已确认或高概率缺陷

| ID | 严重度 | 平台 | 缺陷 | 证据 | 影响 | 建议交接动作 |
| --- | --- | --- | --- | --- | --- | --- |
| BUG-01 | P1 | Android 手机/平板 | 游戏 Activity 固定竖屏 | `GameActivity.kt` 设置 `SCREEN_ORIENTATION_PORTRAIT` | 平板横屏和旋转场景无法按主 App 的设备形态呈现 | 改为按窗口尺寸和游戏布局能力决定方向，补手机/平板方向测试 |
| BUG-02 | P1 | Android/iPhone/iPad | 游戏页面切换主要依赖共享 Web 状态，容器退出时没有统一销毁战斗、Slot 自动旋转、音频和延迟任务的生命周期协议 | `app.js`、`battle.js`、`slots.js` 大量 `setTimeout`、RAF 和全局状态 | 快速退出或切换后可能继续播放音频、继续自动旋转、重复结算或遗留特效 | 增加统一 `pause/resume/destroy`，由原生 `onPause/onDisappear` 调用 |
| BUG-03 | P1 | 三端 | 战斗失败后弹出复活路径，结果状态与战斗状态跨层恢复 | `app.js` 的 `endBattle` 在失败时重新启动 RAF 和复活协议 | 重复点击、返回、系统中断后可能重复结算或卡在失败/战斗状态 | 为战斗结果建立单向状态机并加幂等锁 |
| BUG-04 | P1 | 三端 | 付费礼包和 Slot 充值路径与虚拟币离线模型混在同一流程 | `app.js`、`slots.js` 存在 `recharge-pay`、SSR 礼包、VIP 和充值弹窗 | 产品规则、测试边界和用户预期不一致，容易造成错误购买语义 | 明确是否纯虚拟币。若是，移除真实付费文案和入口 |
| BUG-05 | P1 | iPad | iPad 使用共享 Web 盘面和战斗布局，没有独立宽屏/横屏信息层级 | iOS 游戏容器只提供 WKWebView，布局集中在 `app.css` | 可能出现 Slot 盘面过小、战斗 HUD 空洞或角色比例失衡 | 建立 iPad 断点和横屏截图基线 |
| BUG-06 | P1 | iPhone/iPad | Web Canvas 战斗与 Slot 控件没有完整可访问语义 | 主要内容由 Canvas、动态 HTML 和浮层组成，未见端到端 VoiceOver 证据 | VoiceOver 无法读取战斗状态、Slot 结果和奖励 | 增加状态播报区、结果语义、焦点管理和 VoiceOver 测试 |
| BUG-07 | P2 | Android | WebView 固定 `textZoom=100` | `GameActivity.kt` | 系统字体放大不会传递到游戏，长文本和辅助阅读受影响 | 使用相对布局与可测试的字体缩放策略 |
| BUG-08 | P2 | Android | WebView 控制台消息被吞掉 | `onConsoleMessage` 直接返回 `true` | 线上资源、Spine、音频和脚本错误难以定位 | Debug 保留日志，Release 输出受控错误事件 |
| BUG-09 | P2 | iPhone/iPad | iOS 控制胶囊覆盖 WebView，但游戏内部没有统一安全区 token | `GameContainerView.swift` 外层安全区与 Web CSS 各自处理 | 顶部 HUD、返回按钮和游戏内容可能重叠 | 将容器安全区传入 Web CSS 变量并测试刘海、横屏和 iPad |
| BUG-10 | P2 | 三端 | `prefers-reduced-motion` 只覆盖部分 CSS/Spine/动画路径 | `app.css`、`spine.js`、`vfx.js` 有分支，但视频、音频、震动和延迟任务未形成统一策略 | 减少动态效果用户仍可能遇到闪屏、震动和大范围爆闪 | 建立统一 MotionPolicy 并覆盖所有反馈通道 |
| BUG-11 | P2 | 三端 | Slot 中奖线、Near-Miss、大奖立绘和 CG 叠加时序复杂 | `slots.js` 同时控制停轮、中奖线、奖励浮层和视频 | 自动旋转、返回和重复点击时可能遮挡或无法继续 | 用明确的 idle/spinning/result/feature 状态机替代散落延迟 |
| BUG-12 | P2 | 三端 | 战斗速度、跳过、技能和结果回调共用 RAF/定时任务 | `app.js`、`battle.js` | 跳过或切速时可能产生视觉与数值不同步 | 增加固定步长模拟与单次结算断言 |
| BUG-13 | P2 | 三端 | 动态 HTML 插入依赖字符串模板，内容安全和文本转义边界不统一 | `ui.js`、`battle.js`、`tactical-hud.js`、`slots.js` 大量 `innerHTML` | 本地数据损坏或未来远程内容进入时可能造成布局或脚本注入 | 对动态数据统一文本节点和允许标签白名单 |
| BUG-14 | P3 | 三端 | Android 退出胶囊可拖动，位置没有持久化和安全区校正 | `GameActivity.kt` 的触摸拖动逻辑 | 可能被拖到系统手势区或遮挡关键内容，重进后位置行为不一致 | 限制可停靠区域并在窗口变化后重新校正 |

## 三端专项结果

### Android 手机

- 主风险是固定竖屏、系统字体不跟随、WebView 错误不可见和返回/退出状态未做完整中断测试。
- 需要验证系统返回、手势返回、锁屏、后台恢复、旋转锁定、低内存重建和音频焦点。

### Android 平板

- 与手机共用 Activity 方向和 Web 布局，未形成平板专属信息层级。
- 需要验证 7 至 13 英寸窗口、横竖屏、分屏、键盘/鼠标、触控目标和大字号。

### iPhone

- 原生控制胶囊和 Web 内容叠加，需验证安全区、系统返回手势、后台恢复、静音同步和动态字体。
- 游戏内 Canvas 语义和奖励结果 VoiceOver 仍未关闭。

### iPad

- 游戏未证明复用了主 App 的 iPad 侧边栏、宽屏网格和横屏布局成果。
- 必须单独验证大画幅、横屏、分屏、浮动键盘、指针和 VoiceOver。

## 验证缺口

- 没有四类设备的同版本截图和录屏。
- 没有战斗 1000 次运行中的中断、跳过、复活和重复点击测试。
- 没有 Slot 10000 次分布、自动旋转中断和免费旋转恢复测试。
- 没有三端 VoiceOver/TalkBack、动态字体、减少动态效果和色觉测试。
- 上一轮 iOS Archive 曾因 Xcode `build.db: disk I/O error` 阻断，当前不能用 OTA 包作为本轮验证证据。

## 给 Antigravity 的执行顺序

1. 先修复 BUG-01 至 BUG-06，建立三端容器状态协议和设备矩阵。
2. 再修复 BUG-07 至 BUG-12，统一字体、MotionPolicy、游戏状态机和结果幂等性。
3. 最后处理 BUG-13、BUG-14 与视觉细节。
4. 每个阶段必须产出 Android 手机、Android 平板、iPhone、iPad 的大厅、战斗、结果、Slot 待机、旋转、中奖和退出恢复截图。
5. 完成设备回归后再执行双端签名构建和 OTA 发布。
