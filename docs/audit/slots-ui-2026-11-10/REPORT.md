# Slots UI 与动画设计审计报告

日期：2026-11-10  
范围：`app/src/main/assets/www/index.html`、`css/app.css`、`js/slots.js`、`data/slots.json`、Slots 相关静态资源。  
审计方式：本地 HTTP 服务 + Playwright 浏览器实测，覆盖进入 Slots、静态首屏、点击 SPIN、奖励弹层、结算状态。审计只提交报告，不修改业务代码。

## 结论

当前 Slots 的主屏结构已经形成清晰的“奖池 → 滚轮 → 结算 → 辅助控制 → 伴游/主操作”层级，桌面宽视口下没有观察到控制条横向溢出。核心旋转流程可完成，中奖后能显示连线高亮、收益和奖励弹层。

当前存在一个可复现的 P1 视觉功能缺陷，以及数个 P1/P2 级设计和可访问性风险。最高优先级问题是奖励弹层会为部分符号拼接不存在的资源路径，浏览器实际请求 `assets/heroes/undefined/nude.webp`，导致奖励展示区域空白。

## 发现的问题

### P1 · 奖励弹层请求不存在的 `undefined/nude.webp`

证据：当前浏览器控制台记录了：

```text
Failed to load resource: the server responded with a status of 404
/assets/heroes/undefined/nude.webp
```

触发路径是一次普通二连奖励。`showFeature()` 在 `slots.js` 中使用 `hero.key` 拼接奖励立绘路径。当符号解析到敌方或未注册英雄时，`hero` 存在但 `hero.key` 缺失，最终生成 `assets/heroes/undefined/nude.webp`。弹层仍然打开，造成“奖励标题存在、主视觉空白”的断裂体验。

影响：

- 中奖反馈的主视觉缺失。
- 404 会污染 WebView 控制台并增加无效请求。
- 用户无法判断是动画尚未加载，还是奖励资源损坏。

建议修复方向：先验证 `hero.key` 和资源文件存在，再决定使用 `artWeb`、符号图标或明确的占位状态。资源缺失时应保留可见的符号卡片或错误状态，不应渲染空舞台。

### P1 · 奖励弹层的自动关闭时序削弱了用户控制

`showFeature()` 等待约 1.1 秒后自动播放 CG，随后直接调用 `hideFeature()`。弹层虽然提供“继续”按钮，但自动流程不等待用户操作，按钮无法真正控制完整展示时长。

影响：

- 用户尚未读完标题和奖励文案，弹层可能已自动消失。
- 自动 Slots 连转时，奖励弹层与下一轮之间缺少清晰的确认边界。
- `aria-modal="true"` 的模态状态与自动关闭行为不完全一致。

### P2 · 旋转状态的动效节奏与信息层级不一致

旋转流程同时使用滚轮旋转、分轴停止、窗口 bounce、突入立绘、音效、震动和结算高亮。动效资源丰富，但缺少统一的阶段提示。当前截图中，奖励弹层占据整个视口，背景仍保留完整 Slots 画面，视觉焦点集中但上下文被强烈压暗。

建议将旋转拆成明确的三段节奏：启动、分轴停止、结算。突入立绘只在大奖或明确触发条件下出现，普通中奖避免与连线高亮同时争夺视觉焦点。

### P2 · 窄屏断点仍存在潜在的文字和控制压缩风险

`@media (max-width: 600px)` 将辅助按钮压缩到 9.5–10px，并将 LAST WIN 辅助文案设置为省略号截断。该策略能避免布局溢出，但会牺牲可读性与状态完整性。当前桌面截图无法证明 393pt、466pt 外屏和 669pt 内屏下没有腰斩或信息丢失。

重点风险区域：

- `赔率表 / MAX / AUTO / TURBO` 同行布局。
- `单次旋转消耗...` 状态提示。
- SPIN 按钮副标题。
- 伴游名称切换按钮。
- 奖励弹层标题与引号文案。

### P2 · 伴游区的交互语义不完整

伴游画布带有 `aria-label`，外层使用 `title="轻触特勤互动"`，但实际可操作区域是 `div`，不是按钮。键盘和辅助技术无法可靠发现“点击伴游会触发互动”。

建议将互动区域改为语义化按钮或增加键盘事件、焦点样式和明确的可访问名称。

### P2 · 减少动态效果模式覆盖不完整

全局 `prefers-reduced-motion` 会把 CSS 动画压到极短时长，但 Slots JavaScript 仍根据 `state.settings.reduceMotion` 控制等待时间、突入动画和分轴停止。系统偏好与应用内设置不是同一来源，可能出现 CSS 已静止而 JS 仍触发突入、震动和音效的情况。

建议统一动效开关来源，并在减少动态效果时同步关闭突入立绘、震动和非必要音效。

### P3 · 顶部标题和奖池信息在窄高视口下占用固定空间

Slots 顶栏、奖池条、机台标题和滚轮标签均同时占用垂直空间。`max-height: 620px` 只处理了通用页面，没有专门压缩 Slots 的顶部信息层。横屏手机或折叠屏外屏可能优先压缩滚轮与操作台。

## 做得较好的部分

- 主操作 SPIN 使用单一大型按钮，触控目标明确。
- 下注控制已从右侧操作翼抽出为独立辅助条，桌面截图中没有发现原先的横向截断。
- 奖池、LAST WIN、免费旋转状态都有独立语义区域。
- `aria-label`、`aria-pressed`、`role="dialog"` 和按钮名称覆盖了主要控制元素。
- 旋转结束后连线高亮、收益数字和状态徽章形成可理解的反馈闭环。
- `prefers-reduced-motion` 和应用内 `reduceMotion` 都已存在，说明动效降级已有设计入口，但需要统一。

## 证据限制

- 本轮使用桌面浏览器视口完成截图，未对真实 iPhone、Duo 外屏/内屏、iPad 横竖屏进行逐一截图验收。
- 本轮未验证原生 Android WebView 与 iOS WKWebView 的字体度量、safe-area 和触觉反馈差异。
- 本轮未修改代码，因此没有验证修复后的回归结果。

## 建议优先级

1. 修复奖励弹层的 `hero.key` 空值与资源存在性校验，并补充普通英雄、敌方符号、Wild 和 Scatter 的展示回归用例。
2. 明确奖励弹层的关闭策略，决定由用户点击“继续”还是由自动流程关闭，并让按钮语义与行为一致。
3. 在 393pt、466pt、669pt、iPad 宽屏和横屏视口下重新截屏，重点检查控制条、状态文案、奖励弹层和 SPIN 按钮。
4. 统一系统减少动态效果、应用设置、震动和音效的降级策略。
5. 将伴游互动区域改为可聚焦、可键盘触发的语义化控件。
